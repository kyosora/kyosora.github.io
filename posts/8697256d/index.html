PowerShell 從登錄檔匯出 Windows 已安裝軟體清單

發表於2025-01-02|系統與維運
|總字數:1.3k|閱讀時間:4分鐘

用 Win32_Product 盤點 Windows 軟體有兩個問題：它只看 Windows Installer（MSI）產品，而且查詢時可能啟動每個 MSI 套件的一致性檢查。盤點工作不該順便觸發修復。

比較實用的做法，是讀取「應用程式與功能」背後的 Uninstall 登錄檔。它涵蓋的軟體比 Win32_Product 多，也沒有 MSI 驗證的副作用。不過先把界線講清楚：Windows 沒有一個來源能列出電腦上的所有軟體，登錄檔清單也會漏掉可攜式程式、部分 Microsoft Store 套件與其他使用者範圍的安裝。

為什麼避開 Win32_Product？

Microsoft 的 PowerShell 文件明確提醒，Win32_Product 查詢很慢，而且會驗證並嘗試修復已安裝的 MSI 套件。應用程式事件記錄裡可能因此出現一批 MsiInstaller 事件。

登錄檔查詢只是讀取解除安裝資訊，風險低很多。這篇腳本掃三個位置：

  • HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall：64 位元、整台電腦範圍。
  • HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall：64 位元 Windows 上的 32 位元軟體。
  • HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall：目前登入使用者的安裝。

請用 64 位元 PowerShell 執行。若在 32 位元 PowerShell 裡跑，登錄檔重新導向會讓兩個 HKLM 視圖更難判讀。

可直接執行的腳本

下面是整理過、方便重複執行的版本。它只讀登錄檔，最後在桌面寫出 CSV，不需要管理員權限。

去重不能只看軟體名稱

舊版腳本用了 Sort-Object DisplayName -Unique。這會把同名的不同版本合併，例如機器同時保留兩個 SQL Server 元件或不同架構的 runtime，最後只剩一筆。

新版用名稱、版本與發布者三個欄位一起判斷。它仍不是完美主鍵，因為登錄資訊由安裝程式自行填寫；但比只看名稱安全，也保留 side-by-side 安裝。

InstallDate 也不要直接當成可靠日期。常見格式是 yyyyMMdd，有些安裝程式不寫，有些更新後會改值。這個欄位適合協助排序，不適合單獨當成軟體首次安裝的稽核證據。

哪些軟體仍然不在清單裡？

Microsoft 文件也說，沒有保證能找出系統內每一個應用程式。這支腳本主要對應傳統 Win32 程式：

  • 可攜式程式沒有安裝程序，通常不會寫 Uninstall key。
  • 只掃目前使用者的 HKCU，看不到其他使用者自己的安裝紀錄。
  • Microsoft Store 的 MSIX／Appx 套件有自己的套件資料。
  • 部分企業部署工具或安裝程式沒有正確填寫 DisplayName、版本與發布者。

若還要盤點目前使用者的 Store 套件，可以另外執行：

Get-AppxPackage 回傳的是套件，不等同「應用程式與功能」裡的一列，也不該直接和登錄檔資料硬去重。需要全機資產盤點時，還要定義使用者範圍、可攜式程式的判定方式，以及是否納入系統元件；先寫清楚盤點規格，比宣稱一支腳本能拿到「完整清單」實際得多。

我會怎麼用這份結果

單機交接、重灌前備份或客服排查，這份 CSV 已經很夠用。企業資產管理則只能把它當其中一個資料源，還要配合端點管理平台、套件管理器與使用者清單。

下次看到 Win32_Product 的盤點腳本，我會先換成登錄檔查詢，再確認需求到底是「目前使用者可解除安裝的程式」還是「整台電腦上所有可執行軟體」。這兩題的答案不同，腳本也不可能只差一個參數。
