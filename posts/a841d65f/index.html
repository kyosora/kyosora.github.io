OpenAI 要買 Promptfoo：Agent 安全測試該測什麼

發表於2026-03-12|AI工具實戰資訊安全
|總字數:1.9k|閱讀時間:6分鐘

2026 年 3 月 9 日，OpenAI 宣布「將收購」Promptfoo。這個時態不能省略：OpenAI 公告寫明交易完成仍要符合一般成交條件，並說完成後才會把 Promptfoo 技術整合進 Frontier。

所以目前能確認的是收購協議與產品方向，不能把「安全掃描已經成為 Frontier 原生功能」寫成完成式。公告同時承諾會繼續開發 Promptfoo 的開源 CLI 與函式庫，這才是現在就能使用的部分。

Agent 安全測試比聊天輸出多一層

聊天機器人答錯，傷害可能停在畫面上的文字；連上工具、資料庫、email 與檔案系統的 agent，輸出可能成為下一個程式的輸入，最後真的執行動作。

這不代表傳統聊天機器人沒有資料外洩風險。只要接了 RAG、對話紀錄或內部搜尋，它一樣可能洩漏敏感內容。Agent 多出來的風險，是模型還能選工具與組合操作：

  • 讀到網頁裡的惡意指令後，把內部資料送到外部網址。
  • 用一般使用者身份呼叫只有管理員能執行的 tool。
  • 在參數 schema 合法的情況下，查詢不屬於這名使用者的訂單。
  • 把一次核准重播到不同金額、不同收件人或不同檔案。

安全測試若只問「模型會不會說出危險句子」，會漏掉真正重要的工具副作用。

Prompt injection 很像 SQL injection，但解法不同

兩者都從不受信任輸入開始，這個類比有助於理解攻擊面。差別在於 SQL 有清楚的資料與指令語法，參數化查詢可以建立可靠邊界；LLM 把系統指令、使用者文字與外部文件都放進同一段上下文，沒有等價的「參數化 prompt」能徹底消除注入。

官方文件寫的是掃描 50 多種弱點類型，預設執行時可能產生數百個對抗輸入。測試數量取決於選到的 plugin、strategy 與 numTests，不能把「固定會跑幾百種攻擊 pattern」當成產品規格。

還要注意資料流。掃描器可以在本機執行，但對抗樣本生成與評分仍可能呼叫設定的模型供應商或 Promptfoo 遠端服務。正式資料、憑證與客戶個資不該直接塞進測試案例；先確認 provider、網路出口和資料保留政策。

CI 不該每天隨機打同一扇門

Promptfoo 的 CI/CD 文件建議用 --fail-on-error 或明確的通過率門檻控制建置。這比讀 $? 後自己假設所有失敗都有相同 exit code 更清楚，也能把報告保存成 artifact。

完整 red team 成本較高，還可能受攻擊模型與評分模型的隨機性影響。我會把它放在排程、正式發布前或權限模型變更後執行，再把確認過的失敗案例收回固定 eval。這樣 PR gate 測的是可重現的退步，red team 負責找新的未知案例。

測試案例要碰到真正的授權邊界

一個能查訂單的 agent，至少要測四層：

  1. 模型是否拒絕明顯越權要求。
  2. 模型即使產生錯誤 tool call，後端是否仍拒絕。
  3. 使用者能否改參數讀到別人的物件，包含 BOLA／IDOR 類型問題。
  4. 間接注入能否讓 agent 對外傳輸資料或串接多個 tool 擴大權限。

例如測試「只能讀自己的訂單」，不能只比對回答文字：

這段是測試邊界的示意碼，實際 assertion 要接你自己的 trace 與 audit log。關鍵在於後端根據登入 principal 判斷訂單所有權，不能相信模型傳入的 userId 或 isAuthorized。

掃描通過也不能替代架構防線

Promptfoo 可以幫忙找失敗案例，無法證明某個 agent 對所有未知 prompt 都安全。LLM 行為會隨模型版本、系統提示、外部資料與對話上下文改變，測試只能覆蓋採樣到的路徑。

OWASP AI Agent Security Cheat Sheet給的方向更接近工程底線：

  • 模型提出動作，政策元件獨立檢查權限與參數。
  • Tool 用登入 session 的 principal 執行，不接受模型自報身份。
  • 帳號恢復、付款、刪除與權限變更要求升級驗證。
  • 核准綁定確切工具、目標、參數、期限，不能重播到別的動作。
  • 外部文件一律視為不受信任資料，限制 agent 的網路出口與可用工具。

原文建議「過濾已知 injection pattern」，這可以留在偵測層，不能當主要防護。字串過濾漏掉一個變形就失守；後端授權即使遇到模型誤判，仍應拒絕不合法操作。

這筆交易真正傳出的訊號

OpenAI 願意買下 Promptfoo，顯示企業 agent 平台需要安全測試、追蹤與治理能力。它不等於某個工具已經解決 prompt injection，也不能證明產業部署率或安全成熟度；收購公告本身只承諾未來整合方向。

如果 agent 已經有工具權限，我會先做兩件事：把已知越權案例寫成可重現 eval，再檢查錯誤 tool call 是否會被後端擋下。紅隊掃描可以幫忙找下一個洞，但第一個洞通常早就藏在「模型傳什麼，後端就做什麼」的介面裡。
