Docker 基礎概念

Docker 是一個開放原始碼的容器化平台，把應用程式和依賴項打包成容器。映像能減少環境差異，但 CPU 架構、kernel、volume、secret 與外部服務仍會影響結果；容器不等於百分之百相同的執行環境。

這篇假設你已經有 api/ 與 frontend/ 兩個可在本機執行的專案，重點是容器化與整合。若要建立最小骨架，可先跑：

資源管理與監控

容器資源限制

下面的片段展示如何替主 docker-compose.yml 裡的 api 和 db 服務加上本機 Docker Engine 可直接套用的資源限制。這些欄位要合併進既有服務，不能整段取代原本的 image、environment、entrypoint、secrets、volumes 與 healthcheck。

Compose 規格把 deploy 定義成可選實作，不同平台可能忽略整段。這裡改用服務層的 cpus、mem_limit 與 mem_reservation，比較適合本機 docker compose up。套用後仍要以 docker inspect 與 docker stats 確認限制真的進入容器設定；mem_reservation 只是記憶體壓力下的軟限制，不代表主機一定保留這塊記憶體。

要限制資料庫佔用的磁碟空間，實務上做法是控制掛載 volume 所在的底層磁碟或分割區配額，而非依賴 Compose 的 storage_opt——storage_opt 只在特定 storage driver（如 devicemapper）下有效，overlay2 等常見驅動並不支援。

常見問題與解決方案

1. SQL Server 連線問題

  • 確認連線字串中的主機名稱使用服務名稱 (db)
  • 確認 SA 密碼符合複雜度要求
  • 檢查防火牆設定
  • 連線字串記得帶 TrustServerCertificate=True。從 Microsoft.Data.SqlClient 4.0（.NET 6 時期）起，連 SQL Server 預設 Encrypt=true，會去驗證伺服器憑證。容器裡的 SQL Server 用的是自簽憑證，用戶端不信任就會丟「The certificate chain was issued by an authority that is not trusted」而連不上。這也是這個技術棧最常見的「照抄就壞」狀況。正式環境若要真正加密，應該換成受信任的憑證，而不是長期靠 TrustServerCertificate=True 跳過驗證。

2. .NET Core API 容器化問題

  • 專案名稱不符：Dockerfile 裡 COPY ["YourProject.csproj", "./"] 和 ENTRYPOINT ["dotnet", "YourProject.dll"] 的名稱必須和實際 .csproj 檔名一致。restore／publish 失敗會讓 Docker build 以非零狀態停止；若建置成功但 DLL 名稱不符，則會在容器啟動時找不到 entrypoint。先看 build log，再用 docker run --rm --entrypoint ls <image> /app 檢查產物。
  • ASPNETCORE_HTTP_PORTS 問題：.NET 8 之後的 ASP.NET Core Linux 映像預設監聽 8080。確認 Compose ports 的容器端（右邊）與 ASPNETCORE_HTTP_PORTS 對齊；本文的 5000:8080 代表從主機 5000 轉到容器 8080。舊式 WebHost.CreateDefaultBuilder() 專案可能不認新變數，這時要明確設 ASPNETCORE_URLS=http://+:8080。
  • 埠號衝突：本機已有其他服務佔用 5000 port 時，docker run -p 5000:8080 會直接報 address already in use。改換主機端口（左邊數字）即可，容器內部不受影響。

3. Vue3 建置問題

  • node_modules 沒被忽略：若 .dockerignore 漏了 node_modules/，COPY . . 會把本機的 node_modules 全複製進去，覆蓋 npm install 的結果，且映像會暴增幾百 MB。確認 .dockerignore 有這一行，並用 docker build --no-cache 重新建置。
  • 環境變數 .env 問題：Vite 建置時只把 VITE_ 前綴的變數打包進靜態檔，普通的環境變數不會帶入。若前端無法讀到 API URL，確認 .env 裡是 VITE_API_URL=... 而非 API_URL=...，並確認 .env 在 COPY . . 之前已存在（或改在 npm run build 時以 --mode 指定）。

4. 效能優化相關

映像檔優化

  • 多階段建置：確認 Dockerfile 最終 FROM 用的是 aspnet 而非 sdk，再用 docker image inspect 與 docker history 比較自己的映像。大小會隨 CPU 架構、runtime、套件與 globalization 資料改變，不預設固定 MB 數。
  • alpine 基底：nginx 可評估 Alpine 版；.NET 的 Alpine 映像使用 musl libc，部分原生 NuGet 套件與 globalization 行為不同。先跑完整測試再換，不只為了帳面大小改基底。
  • .dockerignore：至少要排 bin/、obj/、.git/、node_modules/。可以用 docker history <image> 觀察每個 layer 大小，找出意外肥大的 COPY 步驟。

容器效能優化

  • 資源限制設定後確認有效：docker stats 會顯示每個容器的 CPU/記憶體即時使用量與上限，設完就用這個確認限制是否生效。
  • Volume vs bind mount：Docker Desktop 的檔案共享機制、VirtioFS／WSL2、檔案數與讀寫型態都會影響結果。資料庫資料用 Volume，原始碼開發才用 bind mount；速度差多少用相同資料與工作負載量測，不套通用倍數。
  • 清理指令：docker system prune -f 一次清掉停止的容器、無用 network 和 dangling image；加 -a 會連沒在用的 image 一起刪，空間不夠時再用。

網路效能

  • 同一個 Compose 專案的服務自動在同一個 bridge network 裡，用服務名稱（如 db、api）互連，不需要走 host port，延遲遠低於繞出去再繞回來。
  • 需要前後端隔離時，按本文「網路配置」一節建立 backend internal: true，只讓 API 跨兩個 network，不要讓 frontend 直接碰到 db。

安全性建議

除了之前提到的最佳實踐外，還要注意：

容器安全

read_only: true 把根檔案系統設成唯讀；/tmp 另掛 tmpfs 才能容納暫存檔。若 API 使用 Cookie、anti-forgery 或其他 ASP.NET Core Data Protection 功能，還要把 key ring 掛到持久且受保護的 volume（例如 /home/app/.aspnet/DataProtection-Keys）並限制權限；否則容器重建後舊 Cookie 會失效。純 Bearer token、沒有 Data Protection 狀態的 API 才能只用上面的最小片段。

非 root 使用者

「使用非 root 使用者執行容器」要在 Dockerfile 裡真的設定。.NET 8 之後的官方 Linux 映像已內建 app 使用者與 $APP_UID，不必再自行 adduser：

SQL Server 官方映像（mssql/server）已內建用 mssql 使用者跑，不需要額外設定。

機密管理

前面的主 Compose 已示範完整接法：服務各自取得需要的 secret、SQL Server 啟動程序讀入 sa_password、初始化工作建立低權限帳號，.NET API 再從 /run/secrets/app_db_password 組連線字串。只寫一段 secrets: 宣告卻沒讓程式讀檔，密碼不會自動出現在 IConfiguration，那種範例看起來安全，實際上服務會因為拿不到密碼而啟動失敗。

最佳實踐建議

  1. 安全性考量

    • 不要在映像檔中存儲敏感資訊
    • 定期更新基礎映像檔
    • 使用非 root 使用者運行容器

  2. 開發流程

    • 使用 docker-compose.override.yml 管理開發環境設定
    • 實作健康檢查機制
    • 建立完整的 CI/CD 流程

結論

本文涵蓋了以下幾個核心部分：使用 .NET 10 LTS 的多階段建置、含 healthcheck 與低權限資料庫帳號初始化的 docker-compose.yml、Hot Reload 開發環境設定、nginx history mode 路由修正，以及常見問題的排查方向。

後續建議把非機密設定依開發／staging／正式環境分層，密碼繼續交給部署平台的 secret store，再接上 CI/CD 自動建置與映像弱點掃描。環境差異應留在設定與 secret 掛載，不要烤進映像檔。
