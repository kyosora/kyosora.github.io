bat 用 if errorlevel 1 檢查失敗？結束代碼是負數就會漏接，照樣往下部署

發布於 2026-11-26 約 6 分鐘讀完

這個部落格是用一支 deploy-hexo.bat 發佈的：npm run clean、npm run build、npm run deploy 三步。昨天換佈景主題時，我要它在任何一步失敗時停下來，壞掉的產物不要推上 GitHub。

前後換了三種寫法，前兩種都有洞，兩個洞都是送 Codex 審查時被抓出來的。第一個洞會把負的結束代碼當成成功，第二個洞則是修第一個洞時換來的。

第一版：if errorlevel 1

很常見的一種寫法：

if /? 的說明寫得很清楚，ERRORLEVEL number 的意思是「上一個程式的結束代碼大於或等於這個數字」：

大於或等於 1，負數就不算。負的結束代碼聽起來像邊角情況，寫這篇時我在本機試了一次：讓一個程式用 0xC0000005（存取違規，程式崩潰時常見的代碼）結束。

cmd 把結束代碼當成有號整數，0xC0000005 變成 -1073741819。這類 0xC... 開頭的代碼在 cmd 裡都會是負數，if errorlevel 1 全部漏接。這裡是我用 Python 主動回傳存取違規的代碼；只要 call npm run build 最後傳回負數，第一版就會繼續執行 deploy。至於 Node 真的崩潰時，經過 npm 最後會回什麼，我沒有實測。

第二版：存成 rc，再跟 0 比

改成把結束代碼存起來，只要不是 0 就停：

正數、負數都擋得住。Codex 審第二版時又指出一個洞：%ERRORLEVEL% 不一定是真的結束代碼。

同一份 if /? 的說明後面有一段：

只要環境裡有一個叫 ERRORLEVEL 的變數，%errorlevel% 拿到的就是那個變數，不是上一個程式的結束代碼。像是在同一個命令列視窗裡有人下過 set ERRORLEVEL=0，或是某支包裝腳本把它設進環境。

這個洞是審查時從說明文件推出來的，我平常部署時沒遇過，這台電腦的使用者和系統環境變數裡也沒有 ERRORLEVEL。但只要外層設過 ERRORLEVEL=0，build 失敗後腳本還是會呼叫 deploy，所以我把這個情境也補進測試。

if errorlevel N 那種寫法不受這個影響，它讀的一定是真的結束代碼。我想保留第二版跟 0 比的寫法，剩下要解決的就是同名變數。

第三版：先清掉同名變數

setlocal 讓清變數、設 rc 都只在這支 bat 裡生效，不會漏回呼叫它的那個視窗。EnableExtensions 是明確打開命令延伸功能：set /? 寫得很清楚，%ERRORLEVEL% 這類動態變數要在延伸功能開啟時才有，而且「使用者自己定義了同名變數，就會蓋過動態的那個」。清掉同名變數後，我在每個 call 的下一行就把 %errorlevel% 存進 rc，記下那一步的結束代碼。存成 rc 再跟 0 比，正數和負數都擋得住。實際的 deploy-hexo.bat 還多了 chcp 65001、幾行提示文字和結尾的 pause，這裡拿掉了。

用假的 npm 跑完整個矩陣

這種錯誤處理，只跑一次成功的部署什麼都驗不到。我請 Claude Code 搭了一個測試環境（下面是寫這篇時重跑的結果）：一支假的 npm.cmd 放在 PATH 最前面，依環境變數決定哪一步回什麼代碼，每次被呼叫都記到檔案裡。

三種寫法，各跑「外層環境（沒設、ERRORLEVEL=0、ERRORLEVEL=7）× 結果（全部成功、build 回 2、build 回 −1）」九種組合，看實際呼叫了哪幾步、最後的結束代碼是什麼。27 格裡有 8 格的行為跟預期不符，合併相同結果如下：

寫法 外層環境 情境 實際呼叫 結果
if errorlevel 1 三種都一樣 build 回 −1 clean → build → deploy 印「完成」，exit 0
存 rc 不清變數 ERRORLEVEL=0 build 回 2 clean → build → deploy 印「完成」，exit 0
存 rc 不清變數 ERRORLEVEL=0 build 回 −1 clean → build → deploy 印「完成」，exit 0
存 rc 不清變數 ERRORLEVEL=7 三種情境都一樣 clean clean 成功後讀到 7，提早中止，exit 1

第三版九格全對：失敗的那幾格都停在 build，沒有跑 deploy，結束代碼是 1；成功的三格都跑完三步，結束代碼是 0。

這次記住的事

第一版漏負數，我換了寫法，結果換來第二版的洞。這個新洞是 Codex 審第二版時指出的：同名變數會蓋過結束代碼。我把外層的 ERRORLEVEL 也放進測試，才重現兩種相反的結果：設成 0，build 失敗照樣部署；設成 7，連成功的 clean 都過不了。只在乾淨的環境裡把正負結束代碼測一遍，第二版會全部通過。

下次再寫有「失敗就停」的 bat，我會先寫那支假的 npm.cmd，再寫 bat 本身。
