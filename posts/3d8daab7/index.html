使用 SQL Server Resource Governor 限制特定應用程式的資料庫工作負載

發表於2024-08-08|資料庫
|總字數:2k|閱讀時間:7分鐘

1. 背景

某次正式環境使用者抱怨網頁速度極慢，卡了好幾分鐘，我連上 SSMS 查詢也一樣卡。追查後發現另一個專案的排程在跑，CPU 衝高，大型 sort／hash 查詢也在搶 query memory grant，把整台 SQL Server 拖慢。理想解法是切獨立主機，但沒有資源時，Resource Governor 是次佳選項——不需重建環境，先限制那支排程所使用的登入帳號。

版本限制（重要）： SQL Server 2022（16.x）及更舊版本只有 Enterprise 與 Developer Edition 支援 Resource Governor；SQL Server 2025（17.x）起才加入 Standard 與 Standard Developer Edition。請先查 SELECT SERVERPROPERTY('ProductMajorVersion'), SERVERPROPERTY('Edition')，再依實際版本確認功能可用性。

2. Resource Governor 的核心概念

Resource Governor 管理的單位有三層：

  • 資源池 (Resource Pool)：定義 CPU 與記憶體的用量上限，可建立多個池子分別對應不同優先級的工作負載。
  • 工作負載群組 (Workload Group)：關聯到某個資源池，細分同一個池子內的工作分類。
  • 分類函數 (Classifier Function)：每個連線進來時由 SQL Server 呼叫此函數，回傳應該進入哪個工作負載群組的名稱。

這裡有一個會讓整套設定失效的邊界：Resource Governor 分類的是「剛建立的 session」，不是每一條 SQL，也不是目前正在查詢的資料庫。session 一旦被分組，直到連線結束都不會重新分類；中途執行 USE OtherDatabase 也一樣。

所以別用 DB_NAME() 假裝限制整個資料庫。它最多只能看到登入當下的初始資料庫，遇到連線池、跨資料庫查詢或中途切換資料庫就不可靠。我最後採用專用登入帳號：讓高耗用排程固定用 adhoc_batch 連線，再由 classifier 依登入名稱分組。這限制的是那個工作負載，不會誤導成資料庫層級隔離。

重要：MAX 與 CAP 的差異

資源池有兩種 CPU 上限，語意完全不同，常見混淆：

參數 行為
MAX_CPU_PERCENT 軟性上限：只在多個池子互搶 CPU 時才強制執行。伺服器 CPU 空閒時，該資源池可超過此值，甚至用到 100%。
CAP_CPU_PERCENT 硬性上限：不論伺服器是否空閒，該資源池永遠不能超過此值。

若你的目的是「無論如何不讓這個應用程式工作負載超過某個 CPU 比例」，必須用 CAP_CPU_PERCENT。只設 MAX_CPU_PERCENT 在離峰時段不會形成硬限制。

MAX_MEMORY_PERCENT 不能照 CPU 的 MAX／CAP 邏輯類推。對一般磁碟式資料表，它限制的是資源池可取得的 query workspace memory，也就是 sort、hash、索引建立等操作要求的 memory grant；buffer pool 裡的資料頁、索引頁與整個 SQL Server 程序記憶體不在這個上限內。若目標是限制單一查詢的 grant，還要在 workload group 設定 REQUEST_MAX_MEMORY_GRANT_PERCENT。

6. 常見問題

Q：RECONFIGURE 回報「找不到分類函數」
確認函數存在於 master 資料庫，且函數名稱含結構描述（dbo.fn_WorkloadClassifier）。

Q：catalog view 和 DMV 顯示的設定不一樣？
sys.resource_governor_configuration 是已儲存的 metadata；sys.dm_resource_governor_configuration 才是目前生效的記憶體內設定。執行 ALTER RESOURCE GOVERNOR RECONFIGURE 後應以 DMV 驗證，必要時並列兩者找出尚未套用的差異。SQL Server 2022 之後，讀取相關伺服器層 DMV 的非 sysadmin 帳號通常還需要 VIEW SERVER PERFORMANCE STATE。

Q：設了 MAX_CPU_PERCENT = 20，但監控看到 CPU 超過 20%
這是預期行為。MAX_CPU_PERCENT 是軟性上限，伺服器 CPU 空閒時不限制。若需要硬限，改用 CAP_CPU_PERCENT。

Q：Standard Edition 能用嗎？
SQL Server 2022（16.x）及更舊版本不行，只有 Enterprise 與 Developer Edition 支援；SQL Server 2025（17.x）起 Standard 與 Standard Developer Edition 也能使用。
