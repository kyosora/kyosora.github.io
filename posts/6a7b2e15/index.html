Notion MCP 使用教學：用 OAuth 讓 Claude Code 直接操作工作區

發表於2025-06-23|AI工具實戰工具與生產力
|總字數:1.4k|閱讀時間:4分鐘

2026-07 更新： Notion 現在建議使用官方託管的 MCP Server，透過 OAuth 授權。舊版 @notionhq/notion-mcp-server 仍可自架，但官方已停止積極維護，不該再當一般使用者的預設方案。

在 Notion 和 Claude Code 之間來回複製貼上，很快就會變成一件純手工工作。接上 Notion MCP（Model Context Protocol）後，Claude Code 可以搜尋頁面、建立內容、更新資料庫項目；每次寫入前仍應該先確認目標頁面和修改範圍。

什麼是 Notion MCP？

Notion MCP 是 Notion 官方提供的遠端 MCP Server，端點是 https://mcp.notion.com/mcp。它把 Notion 的搜尋、讀取與寫入能力提供給支援 MCP 的工具。

這裡要分清楚兩件事：MCP 負責連接工具；真正能看到哪些內容，仍取決於完成 OAuth 授權的 Notion 使用者本來就有的權限。接上 MCP 不會自動繞過工作區權限。

開始前的準備

需要準備的東西：

  • Claude Code，或其他支援遠端 HTTP MCP 的用戶端
  • 一個 Notion 帳戶
  • 基本的終端機操作能力
  • 大約 5 分鐘

實際可以做什麼

串接完成後，直接跟 Claude 說你要做什麼就好。幾個常用的方向：

  • 「幫我在個人筆記頁面建立一篇關於今天學到的 Python 技巧的筆記」
  • 「把我昨天的會議記錄整理成待辦事項，新增到專案管理資料庫」
  • 「幫我找出所有標記為『重要』的筆記」
  • 「建立本月的工作計劃，包含優先級和預計完成時間」

Claude Code 會透過 MCP 呼叫 Notion。能不能完成某個動作，仍取決於目前工具支援範圍與你的工作區權限；不要把「已連線」理解成所有 Notion 功能都能操作。

常見問題排除

/mcp 顯示未連線？

  • 用 claude mcp list 確認 notion 是否存在
  • 確認 URL 是官方端點 https://mcp.notion.com/mcp
  • 重新執行 /mcp 完成 OAuth；公司網路若擋瀏覽器回呼，換網路或請網管檢查

Claude 說找不到頁面？

  • 先在 Notion 介面確認目前授權帳號真的看得到該頁
  • 用完整標題、資料庫名稱或頁面 URL 縮小搜尋範圍
  • 剛修改的內容可能需要稍等索引更新；精確操作時直接給頁面 URL 比模糊搜尋可靠

一定要用 token 做無人值守流程？

官方託管的 Notion MCP 需要使用者完成 OAuth，不支援 bearer token。完全無人值守的工作可考慮 Notion API，或舊版開源 MCP Server；但後者已停止積極維護，要自己承擔版本與安全更新。不要為了省一次 OAuth，把未維護的套件當預設。

安全性注意事項

  • 只連官方端點；不要把 OAuth 授權交給來路不明的 MCP Server
  • 寫入、移動或刪除前，要求工具先列出目標與變更摘要
  • 共用工作區先拿測試頁驗證，別一開始就對正式資料庫做批次修改
  • 不再使用時，從 Notion 的連線設定撤銷授權

進一步的用法

幾個值得試試的方向：

  • 讓 Claude 替你批次整理筆記格式，比如統一把散落各處的會議記錄整理成固定模板
  • 用 Claude Code 跨頁面搜尋與彙整資料，再附上來源頁面連結
  • 搭配 Claude Code 的程式碼能力，讓它直接把分析結果寫回 Notion 頁面

我會把 Notion MCP 當成「有權限的編輯工具」，不會當成聊天外掛。查詢可以放寬，寫入要縮小範圍；先報告要改什麼，再執行，出錯時才有地方回頭。
