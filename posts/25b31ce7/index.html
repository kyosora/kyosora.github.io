React 與 Vue 共存：Module Federation 怎麼切邊界

發表於2025-06-11|前後端開發
|總字數:1.8k|閱讀時間:7分鐘

公司舊系統是 Vue，新功能想用 React，又不能一次重寫。Module Federation 確實能讓兩套前端在執行時組合，但「載得到遠端 JavaScript」和「React 能渲染 Vue 組件」中間還差一層框架邊界。

這篇原本直接暴露 .vue 檔，再讓 React host 匯入，設定裡還混用了兩套 Vite federation 外掛的選項。那種範例看起來完整，複製後卻會卡在 runtime、型別與生命週期。我把它改成一條比較老實的路：Vue remote 對外暴露 mount()／unmount() 介面，React 只提供 DOM 容器。

Module Federation 只負責載入模組

Module Federation讓不同建置產物在執行時載入彼此暴露的 JavaScript 模組。它處理 remote entry、模組解析和 shared dependency 協商，但不會把 Vue component 自動轉成 React component。

這個跨框架範例刻意不把 vue 放進 shared。Vue runtime 由 remote 自己帶著走，React host 不需要安裝 Vue，也不會和其他 Vue remote 協商版本。代價是多下載一份 Vue runtime；這正是跨框架微前端要付的成本。

shared 設定最容易抄錯

singleton、requiredVersion、eager 是 @module-federation/vite shared 設定的一部分。React、React DOM 這類不能同頁出現不相容副本的依賴，才適合設成 singleton。

@originjs/vite-plugin-federation 是另一套外掛。它的官方 README 目前列出的 shared 物件欄位包含 import、generate、modulePreload 與 requiredVersion；其中 modulePreload 確實是有效欄位。舊稿把它寫成「會被靜默忽略」，剛好和官方文件相反。

外掛名稱、版本、設定格式必須一起寫。只寫「Vite Module Federation 支援某欄位」沒有意義，因為搜尋結果經常把 Webpack、OriginJS 與 Module Federation 官方 Vite 外掛混在同一頁。

真正麻煩的是部署與故障

遠端模組可以獨立部署，也代表 host 每次開頁都要信任另一份正式環境 JavaScript。上線前至少要處理：

  • remote entry 的版本相容與回退方式。
  • 遠端服務逾時、404 或載入失敗時的 fallback。
  • CSP 的 script-src、跨來源 CORS 與正式網域 allowlist。
  • 契約變更的 consumer-driven test。
  • remote 部署後，host 的 smoke test 是否會實際載入它。

Module Federation 不是安全隔離。Remote 程式碼載入後擁有和 host 頁面相近的能力，可以讀取 DOM、呼叫同源 API，也可能影響效能。若兩個團隊不能互相信任，iframe 才提供真正的瀏覽器隔離邊界。

哪些情況值得用？

多團隊需要獨立發布、舊框架必須漸進退場，或單一部署已經成為交付瓶頸時，這套成本有機會回收。

單一團隊、小型網站或兩邊本來就能一起發布時，我不會為了「React 與 Vue 都能用」而加 Module Federation。把 Vue component 包成 Web Component、在同一個 monorepo 建置，甚至先維持原框架，通常更便宜。

我現在判斷這類架構會先問一題：團隊真的需要獨立部署嗎？答案若只是「未來可能需要」，先別把 runtime 網路依賴、雙框架體積與跨團隊契約一起帶進來。
