遠端下一行 Remove-NetRoute，主機就斷線了：Windows 多網卡預設路由怎麼選

發布於 2026-11-26 約 10 分鐘讀完

十月中，一台放在現場的 Win11 主機對外連線時好時壞。我從 AnyDesk 連進去，想調一下路由的優先順序，下了一行 Remove-NetRoute，畫面就凍住了。

後面的事一件接一件：重開機沒救回來；現場補閘道時打錯一個數字；網路通了，AnyDesk 用 ID 還是連不上。一個月後，同一台主機因為無線電換了 USB 孔，又出了一次狀況。

三張網卡，三條預設路由

這台主機接了三張網卡（公網 IP 換成了文件用的保留位址）：

網卡 ifIndex IP 閘道 用途
乙太網路（Intel I219-LM） 21 203.0.113.31/24 203.0.113.254 固定 IP，唯一能上外網
乙太網路 2 20 192.168.11.2 192.168.11.1 無線電的 USB 網卡
乙太網路 5 5 192.168.10.2 192.168.10.1 另一台無線電的 USB 網卡

兩台無線電（MOTOTRBO）用 USB 接上電腦時，會自己當 DHCP 伺服器，發 IP，也發預設閘道。路由表裡因此有三條 0.0.0.0/0，只有一條真的通到外面。

Windows 選路時，先找跟目的 IP 相符、前綴最長的路由。這三條都是 /0，前綴一樣長，才輪到比 RouteMetric 加上 InterfaceMetric 的總和，越小越優先。微軟在 New-NetRoute 的文件裡寫的就是這個加總。查的時候我會把兩個數字加起來排序：

當時的分數：

路由 RouteMetric InterfaceMetric 總和
無線電（ifIndex 20） 0 55 55
無線電（ifIndex 5） 0 55 55
外網卡（ifIndex 21） 256 25 281

這三張卡當時都開著 Automatic Metric。微軟 KB 299540 有一張 Windows 10 以後「其他介面類型」的對照表：200 Mb/s 以上、未滿 2 Gb/s 對應 25；4 Mb/s 以上、未滿 20 Mb/s 對應 55。外網卡在這一項其實贏了，輸在 RouteMetric：DHCP 給的那兩條是 0，外網這條是 256。

兩條無線電路由都是 55，都排在外網的 281 前面。哪一條連線當時實際走了哪張卡，我沒有記下來，只知道對外連線時好時壞。

想把 256 改成 0，結果把出口拔了

Claude Code 看了路由表，說外網那條的 256 不正常。我也覺得只要把 256 壓下來，外網就會贏，打算先刪掉、再用 RouteMetric 0 加回來。第一步是這一行：

按下去，AnyDesk 就斷了。

這一行只帶了「哪張網卡」和「哪個目的地」兩個條件，刪掉的是外網卡唯一的預設路由。準備加回來的那一行，再也送不進去了。

改 metric 其實不需要刪。Set-NetRoute 就有 -RouteMetric 參數，可以原地改數字。

重開機也救不回來

斷線之後，Claude Code 說重開機閘道就會回來。現場人員照著重開，閘道沒有回來，白跑了一趟。那句話是憑印象講的。

Windows 的路由存在兩個地方：ActiveStore 是現在生效的那份，PersistentStore 是開機時載入的那份。New-NetRoute 的文件寫，不指定的話兩邊各存一份；Remove-NetRoute 的 -PolicyStore 則是篩選條件，預設值是空的。

寫這篇時，我請 Claude Code 在我的電腦上用 -WhatIf 跑給我看（只列出會做什麼，不會真的刪）。這台有張代理工具的虛擬網卡，它的預設路由兩個 store 都有：

同一台電腦上，Get-NetRoute -DestinationPrefix 0.0.0.0/0 不帶 -PolicyStore，就 ifIndex 7 這條預設路由來看，只列出 ActiveStore 那份。一般查詢看不到持久那份，同樣的條件交給 Remove-NetRoute，卻把 Active 和 Persistent 一起列進去。

這是事後在另一台電腦上的預演。十月現場能確定的是：重開之後閘道沒有回來，現場人員最後打開網卡內容，把預設閘道重新填回去。刪除前兩個 store 各有什麼，當時沒有留下對照。

至於 256 從哪來：New-NetRoute 不指定 RouteMetric 時，預設就是 256，但單看這個數字，判斷不出這條路由當初是怎麼加的。Claude Code 對 256 的說法前後換過一次，先說不正常，後來又說是手動設閘道的正常值，兩次都沒有依據。

閘道打錯一碼：「無法辨識的網路」

現場人員把閘道填回去時，第一段打錯了一個數字，畫面上是「無法辨識的網路」。對照主機的 IP 是 /24，填進去的閘道根本不在這個網段裡。

我從外面測：上游閘道有回 ping，主機沒有回；主機上預期有服務的幾個 TCP port，我也一一測過，全部逾時。

閘道在網卡內容裡直接改正就好，改欄位是取代，不必先刪再加。改完我確認錯的那個閘道沒留下殘留路由，兩個 store 都要查：

兩個 store 都沒有列出任何東西。要注意 -ErrorAction SilentlyContinue：查不到時 Get-NetRoute 會報錯（中文版是「找不到內容 'NextHop' 等於 … 的 MSFT_NetRoute 物件」），我把它壓掉了，所以空白輸出也可能是查詢本身出錯。要分辨這兩種情況，拿掉這個參數再跑一次。

能上網了，AnyDesk 用 ID 還是連不上

閘道改對後主機能上網，用 AnyDesk ID 卻還是連不上，原因當時沒有查到。從外面測，TCP 7070 已經通了。7070 是 AnyDesk 直接連線的預設 port，我在 AnyDesk 位址欄輸入主機的 IP，這次成功連回桌面。這條路要對方的設定開著「允許直接連線」才走得通。

改完，外網是 256 + 10 = 266，兩台無線電是 500 和 600，預設路由輪到外網。無線電的軟體照樣抓得到機器，因為 192.168.10.0/24、192.168.11.0/24 這兩條直連網段的前綴比 /0 長，跟無線電通訊本來就走它們，不受預設路由的排名影響。

微軟在 KB 299540 裡也提醒，一般不建議在私有網段的網卡上設預設閘道。比較正規的做法是把無線電網卡的 IPv4 改成手動、閘道留空。軟體如果只跟 USB 直連網段上的無線電通訊，保留直連路由就夠；要經過無線電再到別的網段，才需要替那個網段加路由。這次我們先用 metric 解決。

一個月後：換了 USB 孔，Windows 多出兩張網卡

11 月中，要在同一台主機上裝 Tailscale，怎樣都登不進 tailnet。

我回頭查路由表，才發現兩台無線電換過 USB 孔，Windows 把它們當成新裝置，建了兩張新網卡（MOTOTRBO Radio #5、#6）。新網卡回到自動 metric，總分又變成 0 + 55 = 55，外網卡是 256 + 10 = 266。十月調的是舊網卡的 ifIndex，對新網卡完全沒作用。

當時我查了 Find-NetRoute -RemoteIPAddress 1.1.1.1，Windows 選的是外網卡。但我沒有記下 Tailscale 登入時連的目的 IP，這次查詢還原不了它走的路。能確定的是，新網卡的總分是 55，調高之後 Tailscale 隨即上線。

之後在遠端動路由，我守這幾條

  • 能調 metric 就不刪路由。Set-NetIPInterface 調 InterfaceMetric，Set-NetRoute 調 RouteMetric，路由都還在。只是回程一換，現在這條遠端連線仍可能當場中斷。
  • 非刪不可時，帶 -PolicyStore ActiveStore，再加 -NextHop 這類條件縮小範圍，先用 -WhatIf 看會刪哪幾條。-WhatIf 只預覽目標，預演不了改完之後連不連得回來。
  • 動手前先確認退路：現場有人、有獨立的管理通道，或在主機上排好一個到時間就把設定改回去的工作。
  • 定時重開 shutdown /r /t 600 要有條件才用：確認主機重開後會拿回正確的閘道、能從外面連回來，而且現場允許重啟。例如只改了 ActiveStore，開機時還有正確的持久路由可以載入。確認連線正常後，在倒數結束前用 shutdown /a 取消。微軟文件寫明 /t 大於 0 就隱含 /f，時間一到會強制關閉執行中的程式，沒存的資料可能遺失。
  • 「重開機能不能救」是事實問題，下破壞性指令之前先查證。這次的答案是不能。

回頭看，那一行 Remove-NetRoute 想做的事沒錯，外網那條的分數確實該壓低。錯在用刪的去改，又信了一句沒查證的「重開機就好」。下次在遠端碰路由，我會先確認退路，再跑一次 -WhatIf。
