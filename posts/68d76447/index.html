Claude Code 接上 GPT-6：沿用 Codex 登入與 ccx 啟動

發表於2026-09-23|AI工具實戰工具與生產力
|總字數:2.2k|閱讀時間:8分鐘

我想比較 GPT-6 Astra 和 Claude 的差異，但不想連操作介面一起換掉。目標很單純：保留 Claude Code 的工具、權限與操作習慣，只把底層模型換成 GPT-6。

這件事不能只改一個模型名稱。Claude Code 說的是 Anthropic Messages API；CCR 接住請求後，要轉成 openai_responses 格式，再用匯入的 Codex OAuth 憑證送往 Codex backend。我實際用 Claude Code Router（以下簡稱 CCR）接起來，沿用電腦上既有的 Codex 登入，不另外放 OpenAI API key。

先講清楚測試環境

我在 2026-09-23 使用以下版本：

元件 版本
Windows PowerShell 5.1
Node.js 22.22.0
Claude Code 2.1.278
Codex CLI 0.156.0
Claude Code Router 3.1.1
模型 gpt-6-astra

GPT-6 Astra 的官方模型 ID 就是 gpt-6-astra，不是 gpt-6。這點不要猜，模型名稱只要差一個字，後面看到的通常只剩一串 model not found。OpenAI 官方文件能證明模型 ID 與 Responses API 能力；把 Codex OAuth 匯入 CCR，則是 CCR 提供的第三方整合，不是 OpenAI 官方教學流程。

還有一個邊界要先說。CCR 是第三方工具，Anthropic 官方文件也明寫：gateway 可以接，只是把 Claude Code 路由到非 Claude 模型不在官方支援範圍。Claude Code 更新後若新增欄位或工具，gateway 沒跟上，功能就可能退化。

所以我沒有改掉原本的 claude 設定，而是建立一個只在 CCR 內生效的獨立 profile。壞了就關掉，不會連平常使用的 Claude Code 一起拖下水。

匯入 Codex 登入

進入 CCR 管理介面後：

  1. 打開 Providers。
  2. 按 Add Provider。
  3. 在 Import local agent provider 找到 Codex API。
  4. 按 Import。
  5. 協定確認為 OpenAI Responses。
  6. 模型只保留 gpt-6-astra，再執行 Check Connection。

CCR 會讀取本機 Codex 的登入狀態與模型快取，建立 OAuth plugin，之後需要時也會更新 access token。Claude Code 端拿到的是 CCR 自己的本機 credential，不需要把 Codex token 塞進 ~/.claude/settings.json。

如果清單裡沒有 gpt-6-astra，先正常啟動一次 Codex，讓它更新模型快取，再回 CCR 重新掃描或手動編輯模型清單。模型能不能用仍取決於帳號權限；清單裡看得到，不等於帳號一定有額度。

建立獨立的 Claude Code profile

接著到 Agent Config：

  1. 按 Add profile，選 Claude Code。
  2. 名稱填 GPT6-test。
  3. Effect scope 選 Only opened from CCR。
  4. Entry mode 選 CLI only。
  5. Model 選 Codex API/gpt-6-astra。
  6. Opus、Sonnet、Haiku、Fable 等模型欄位也指向同一個模型。
  7. 儲存。

第二個坑：3458 活著，不代表 3456 也活著

另一次啟動失敗時，ccr start --no-open 沒報錯，但 Claude Code 一直說連不到 gateway。檢查連接埠才看到：管理介面的 3458 還在，模型 gateway 的 3456 已經消失。

當時 CCR 記錄的 gateway 結束碼是 0xC000013A，代表程序收到類似 Ctrl+C 的 console control 中斷；它能說明 gateway 為何退出，卻不能單憑這個代碼判定中斷來源。

我同時看到 3458 仍在監聽、3456 已消失，再執行 ccr start --no-open 也沒有恢復 gateway。從結果看，這次啟動沒有重新拉起 3456，形成一種很討厭的假存活。

完整重啟就恢復了：

這樣比較模型，仍然不是純模型評測

這套設定適合回答一個實用問題：在相同 Claude Code 操作介面下，GPT-6 寫程式、呼叫工具與處理長任務的感覺有何不同。

它不能當成嚴格的模型 benchmark。Claude Code 的 system prompt、工具格式、context 管理仍在；CCR 又做了一次協定轉譯。這套流程測到的是「GPT-6 跑在 Claude Code harness 裡」的整體表現，不是裸 API 的 GPT-6。

對我來說這反而更有用。我每天面對的是整個 coding agent，不是模型排行榜。現在 ca 開 Claude Code，cx 開 Codex，ccx 開 Claude Code 加 GPT-6；要比較時不用重配環境，也不用拿同一份設定反覆覆蓋。
